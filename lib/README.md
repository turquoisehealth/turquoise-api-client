# Custom Libraries System - Complete Setup

## 🎯 Overview

This repository supports **manually-coded libraries** that will be bundled into the published SDK packages alongside the Fern-generated code. Users can import these custom utilities just like the generated API client.

## ✨ Key Features

1. **Protected lib directories** - Won't be deleted during Fern regeneration
2. **Automatic export management** - Script updates exports after generation
3. **CI/CD integration** - GitHub workflows automatically maintain exports
4. **Multi-language support** - Python, TypeScript, and C# all configured
5. **Example implementation** - APIAuthHandler utility included

## 📁 Structure

```
├── python/lib/              # Custom Python libraries
├── typescript/lib/          # Custom TypeScript libraries
├── csharp/.../Lib/         # Custom C# libraries
├── scripts/
│   └── update_lib_exports.py  # Maintenance script
├── examples/                # Usage examples for each language
└── .github/workflows/       # ✅ Updated to run export script
```

## 🚀 Quick Start

### For Users (After Package Installation)

**Python:**
```python
from turquoise_health import TurquoiseHealth, APIAuthHandler

auth = APIAuthHandler.from_env()
client = TurquoiseHealth(token=auth.get_token())
```

**TypeScript:**
```typescript
import { TurquoiseHealthApiClient, lib } from "@turquoise-health/api";

const auth = lib.APIAuthHandler.fromEnv();
const client = new TurquoiseHealthApiClient({ token: auth.asSupplier() });
```

**C#:**
```csharp
using TurquoiseHealth.Api.Lib;

var auth = APIAuthHandler.FromEnv();
var client = new TurquoiseHealthApiClient(token: auth.GetToken());
```

### For Developers (Adding New Libraries)

1. **Create your library** in the appropriate `lib/` directory:
   - Python: `python/lib/my_library.py`
   - TypeScript: `typescript/lib/MyLibrary.ts`
   - C#: `csharp/src/TurquoiseHealth.Api/Lib/MyLibrary.cs`

2. **Export it** from the lib module:
   - Python: Add to `python/lib/__init__.py`
   - TypeScript: Add to `typescript/lib/index.ts`
   - C#: Use namespace `TurquoiseHealth.Api.Lib`

3. **Update SDK exports**:
   ```bash
   make update-lib-exports
   ```

4. **Test the import**:
   ```bash
   # Python
   python3 -c "from turquoise_health import MyLibrary"

   # TypeScript
   node -e "const { lib } = require('./typescript'); console.log(lib.MyLibrary)"
   ```

## 🔄 Workflow Integration

### Local Development

After running `fern generate`:
```bash
make update-lib-exports
```

### CI/CD

The GitHub workflows automatically run the update script:
- `.github/workflows/generate.yml` - Updates exports during SDK regeneration
- `.github/workflows/publish.yml` - Updates exports before publishing

## 🛡️ Protection Mechanism

### .fernignore Files

Each SDK has a `.fernignore` file that protects the lib directories:

```
# python/.fernignore
lib/
lib/**
```

This ensures Fern doesn't delete your custom code during regeneration.

### Export Management

The main export files (`__init__.py`, `index.ts`) **are** regenerated by Fern, which is why we need the update script to re-add lib exports after each generation.

## ⚠️ Important Notes

1. **Always run `update-lib-exports` after `fern generate`**
   - The CI/CD workflows do this automatically
   - Locally, use `make update-lib-exports`

2. **lib directories are protected but export files are not**
   - Your custom code in `lib/` is safe
   - Export files get regenerated and need the update script

3. **Follow language conventions**
   - Python: snake_case, docstrings
   - TypeScript: camelCase, JSDoc
   - C#: PascalCase, XML docs

4. **Version carefully**
   - Custom libraries are part of the public API
   - Breaking changes should bump major version

## 🐛 Troubleshooting

**Import not working?**
- Run `make update-lib-exports`
- Check the lib file is in the correct directory
- Verify the export in `lib/__init__.py` or `lib/index.ts`

**Fern deleted my lib directory?**
- Check `.fernignore` exists with `lib/` pattern
- Restore from git: `git checkout python/lib typescript/lib csharp/src/TurquoiseHealth.Api/Lib`

**CI/CD failing?**
- Ensure `scripts/update_lib_exports.py` is executable
- Check GitHub workflows have the "Update library exports" step
