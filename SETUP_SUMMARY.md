## 📦 Features

### 1. Protected Library Directories
- Each SDK has a `lib/` directory for manually-coded libraries
- `.fernignore` files prevent Fern from deleting these directories
- Safe from `fern generate` overwrites

### 2. Example Implementation: APIAuthHandler
All three languages include an `APIAuthHandler` utility class that provides:
- Loading tokens from environment variables
- Static token support
- Dynamic token provider support (functions/callbacks)
- Clean integration with the main SDK client

### 3. Automated Export Management
```bash
# Run after fern generate
make update-lib-exports

# Or directly
python3 scripts/update_lib_exports.py
```

### 4. Full Import Support
Users can import custom libraries alongside generated code:

**Python:**
```python
from turquoise_health import TurquoiseHealth, APIAuthHandler
# or
from turquoise_health.lib import APIAuthHandler
```

**TypeScript:**
```typescript
import { TurquoiseHealthApiClient, lib } from "@turquoise-health/api";
const auth = new lib.APIAuthHandler({ token: "..." });
```

**C#:**
```csharp
using TurquoiseHealth.Api;
using TurquoiseHealth.Api.Lib;
var auth = new APIAuthHandler(token: "...");
```

## 🔄 Workflow

### When Adding a New Custom Library:

1. **Create the library file** in the appropriate `lib/` directory
2. **Export it** from `lib/__init__.py` or `lib/index.ts`
3. **Run** `make update-lib-exports` (or manually update exports)
4. **Test** the imports
5. **Commit** the new library and updated exports

### After Running `fern generate`:

1. **Run** `make update-lib-exports` to restore lib exports
2. **Verify** imports still work
3. **Commit** any regenerated files
